# RDM — دانلود منیجر سریع

هسته‌ی سریع Rust (دانلود چندبخشی + ادامه‌ی دانلود)، برنامه‌ی دسکتاپ با Tauri، و افزونه‌ی مرورگر.

## ساختار پروژه

```
rdm/
  crates/core/         هسته: موتور دانلود + صف + ذخیره‌ی لیست (بدون رابط)
  crates/cli/          نسخه‌ی خط فرمان (rdm.exe)
  src-tauri/           برنامه‌ی دسکتاپ (بک‌اند Rust، سینی سیستم، سرور محلی برای مرورگر)
  ui/                  رابط کاربری (HTML/CSS/JS ساده، بدون نیاز به Node.js)
  extension/           افزونه‌ی Chrome / Edge / Brave
  extension-firefox/   افزونه‌ی Firefox
```

## پیش‌نیازها (ویندوز)

1. Rust از https://rustup.rs (با Build Tools ویژوال استودیو، بخش C++)
2. WebView2 (روی ویندوز ۱۱ و اکثر ویندوز ۱۰ از قبل نصب است)
3. ابزار Tauri (یک‌بار): `cargo install tauri-cli --version "^2" --locked`

## اجرا و ساخت

در پوشه‌ی اصلی پروژه (`rdm`):

```
cargo tauri dev                    اجرای برنامه برای آزمایش
cargo tauri build --no-bundle      ساخت exe:  target\release\rdm-gui.exe
cargo tauri build                  ساخت نصب‌کننده (NSIS)
cargo build --release -p rdm-cli   نسخه‌ی خط فرمان:  target\release\rdm.exe
```

## نصب افزونه‌ی مرورگر

1. برنامه‌ی RDM را اجرا کنید.
2. **Chrome / Edge / Brave:** به `chrome://extensions` (یا `edge://extensions`) بروید، «Developer mode» را روشن کنید، «Load unpacked» را بزنید و پوشه‌ی `extension` را انتخاب کنید.
   **Firefox:** به `about:debugging#/runtime/this-firefox` بروید، «Load Temporary Add-on» را بزنید و فایل `extension-firefox\manifest.json` را انتخاب کنید (افزونه‌ی نصب‌شده به این شکل با بستن Firefox حذف می‌شود؛ برای نصب دائمی باید امضا شود).
3. در RDM: **تنظیمات ← اتصال به مرورگر ← کپی** کد اتصال را کپی کنید.
4. در مرورگر: روی آیکون افزونه ← «تنظیمات افزونه» بروید، کد را جای‌گذاری کنید و «آزمایش اتصال» را بزنید.

بعد از این، هر دانلودی که مرورگر شروع کند به RDM می‌رود (کوکی و Referer هم همراهش فرستاده می‌شود، پس دانلود از سایت‌های نیازمند ورود هم کار می‌کند). اگر RDM بسته باشد، مرورگر خودش دانلود می‌کند.

- راست‌کلیک روی لینک/ویدیو ← «دانلود با RDM»
- آیکون افزونه فایل‌های ویدیو و صوت مستقیم صفحه را نشان می‌دهد (با عدد روی آیکون)؛ روی «دانلود» بزنید.

## امکانات

**نسخه‌ی ۰٫۶ — لینک‌های گروهی، Native Messaging، HLS (جدید):**
- **دانلود همه‌ی لینک‌ها:** آیکون افزونه ← «دانلود همه‌ی لینک‌های این صفحه». فهرست لینک‌ها با فیلتر نوع (ویدیو، صوت، فشرده، سند، برنامه، تصویر)، فیلتر متن و عبارت منظم، تیک‌زدن و ارسال گروهی تا ۵۰۰ لینک. هر لینک فقط کوکی سایت خودش را می‌گیرد.
- **Native Messaging (اختیاری):** برنامه‌ی کوچک `rdm-nm.exe` که خود مرورگر با آن حرف می‌زند. اگر ارتباط مستقیم با RDM ممکن نباشد یا RDM بسته باشد، افزونه از طریق آن کار می‌کند و حتی RDM را باز می‌کند. نصب: در پوشه‌ی خروجی بیلد، `install.ps1` را با `-ChromeExtensionId <شناسه‌ی افزونه>` اجرا کنید (برای Firefox بدون شناسه). روش قبلی (سرور محلی) برداشته نشده است.
- **HLS (`.m3u8`):** لینک‌های HLS ساده (بدون رمز و پایان‌یافته) دانلود و در یک فایل `.ts` ذخیره می‌شوند و بهترین کیفیت انتخاب می‌شود. DASH، پخش زنده و HLS رمزشده با پیام روشن رد می‌شوند. ادامه‌ی HLS از اول شروع می‌شود. افزونه حالا لینک‌های m3u8 صفحه را هم شناسایی می‌کند.
- **برنامه‌ی سرعت:** در تنظیمات، هر خط مثل `22:00-06:00 0` (شب‌ها بدون محدودیت) یا `08:00-17:00 500`.
- **حالت HTTP:** پیش‌فرض HTTP/1.1 با چند اتصال؛ گزینه‌ی «خودکار» HTTP/2 را هم اجازه می‌دهد (HTTP/3 پشتیبانی نمی‌شود).
- **اولویت دانلود** (بالا/معمولی/پایین) در «مشخصات»؛ در هر صف دانلود با اولویت بالاتر زودتر شروع می‌شود.
- **کمتر شدن درخواست‌های اضافه:** نتیجه‌ی بررسی لینک ۶۰ ثانیه نگه داشته می‌شود.
- **ابزار بنچمارک:** `rdm-bench <آدرس> --connections 1,4,8,16 --repeat 3 --max-mib 100` سرعت واقعی را با تعداد اتصال‌های مختلف اندازه می‌گیرد (فقط اندازه‌گیری؛ برای مقایسه با برنامه‌های دیگر باید آن‌ها را هم در همان شرایط اندازه بگیرید).
- **دسترس‌پذیری:** حرکت در فهرست با فلش‌ها، Space، Enter، Ctrl+A و Delete؛ اعلان نتیجه برای صفحه‌خوان.
- فهرست کامل وضعیت هر بخش از سند شما در `IMPLEMENTATION_REPORT.md`.

**نسخه‌ی ۰٫۵ — صف‌ها، پروکسی و تست‌های یکپارچه:**
- **چند صف:** دکمه‌ی «صف‌ها» در نوار بالا. هر صف نام، فعال/غیرفعال، اولویت، تعداد دانلود هم‌زمان، محدودیت سرعت مشترک، ساعت شروع و توقف و عملیات بعد از پایان دارد. صف‌ها در نوار کناری فیلتر می‌شوند. صف‌های با اولویت بالاتر زودتر شروع می‌شوند و مجموع دانلود هم‌زمان همچنان از «تنظیمات» محدود می‌شود. زمان‌بند قدیمی خودکار به صف اصلی منتقل می‌شود.
- **زمان‌بندی درست‌تر:** خاموشی یا هایبرنیت بعد از پایان یک اجرای زمان‌بندی‌شده، به‌طور پیش‌فرض فقط وقتی انجام می‌شود که هیچ دانلودی در آن صف خطا، هش نامطابق یا تهدید نداشته باشد (قابل خاموش کردن برای هر صف).
- **پنجره‌ی مشخصات (Properties):** راست‌کلیک ← مشخصات: تغییر صف، محدودیت سرعت و عملیات بعد از اتمام. دانلود در حال اجرا را باید اول متوقف کنید تا صفش عوض شود.
- **پروکسی:** پروکسی سیستم، بدون پروکسی، یا دستی (HTTP، HTTPS، SOCKS5) با نام کاربری، رمز (رمزشده با DPAPI) و فهرست استثناها. آدرس نامعتبر قبل از ذخیره رد می‌شود.
- **حافظه‌ی تعداد اتصال هر سایت:** اگر سایتی با 429/503 یا قطع اتصال شما را محدود کند، تعداد اتصال مجاز آن سایت ۲۴ ساعت یادآوری می‌شود و دانلود بعدی از همان حد شروع می‌کند (دکمه‌ی «فراموش کردن» در تنظیمات).
- **ماشین حالت:** تغییر وضعیت دانلود فقط از مسیرهای مجاز انجام می‌شود (مثلاً «تمام‌شده» مستقیم به «در حال دانلود» نمی‌رود)، با تست واحد.
- **تست‌های یکپارچه با سرور آزمایشی** (`crates/core/tests/mock_server.rs`): دانلود دقیق بایت‌به‌بایت، 429 با Retry-After، خطای 500، سرور بدون Range، تغییر ETag وسط دانلود، و Content-Range غلط.

**نسخه‌ی ۰٫۴ — صحت فایل و امنیت:**
- **بررسی صحت با SHA-256 و SHA-512:** اگر سرور هش کل فایل را در هدر `Repr-Digest` اعلام کند (یا هدر `Content-Digest` در پاسخ کامل ۲۰۰)، بعد از اتمام دانلود خودکار بررسی می‌شود. وضعیت‌ها: تأیید نشده، در حال بررسی، تأیید شد، مطابقت ندارد. اگر سرور چیزی اعلام نکند، همین را می‌نویسد و می‌توانید هش را خودتان وارد کنید («جزئیات ← جزئیات» یا منوی راست‌کلیک ← بررسی صحت).
  توجه: `Content-Digest` فقط هش همان پاسخ است، نه کل فایل، پس در پاسخ‌های بخشی (206) استفاده نمی‌شود.
- **کوکی امن:** هدرهای هر دانلود (Cookie، Authorization، Referer) قبل از نوشتن روی دیسک با DPAPI ویندوز رمز می‌شوند و فقط همان کاربر ویندوز روی همان کامپیوتر می‌تواند آن‌ها را بخواند. فایل‌های قدیمی که کوکی ساده دارند در اولین ذخیره خودکار رمز می‌شوند. اگر رمزنگاری ممکن نباشد، کوکی اصلاً ذخیره نمی‌شود.
- **اسکن آنتی‌ویروس اختیاری:** در تنظیمات مسیر یک برنامه‌ی اسکنر بدهید (مثلاً Windows Defender)؛ بعد از هر دانلود روی فایل اجرا می‌شود. اگر هش نخواند یا تهدید پیدا شود، فایل حذف نمی‌شود ولی «بعد از اتمام» (باز کردن، خاموشی) اجرا نمی‌شود.
- **ایمنی فایل‌سیستم:** بررسی فضای خالی دیسک قبل از شروع، تغییر نام نهایی بدون بازنویسی هیچ فایل موجود (با چند بار تلاش مجدد اگر فایل موقتاً قفل باشد)، و در شروع دوباره، فایل موقت باید دقیقاً هم‌اندازه‌ی حجم کل باشد وگرنه دانلود از اول شروع می‌شود.

**نسخه‌ی ۰٫۳ — موتور جدید و پنجره‌ی جزئیات:**
- **پنجره‌ی جزئیات برای هر دانلود** (دکمه‌ی «جزئیات»، دابل‌کلیک روی دانلود در حال اجرا، یا راست‌کلیک) با ۵ تب: وضعیت، محدودکننده‌ی سرعت، بعد از اتمام، جزئیات سرور، و اتصال‌ها. همه‌ی مقدارها از وضعیت زنده‌ی موتور Rust می‌آیند و هر ۲۵۰ میلی‌ثانیه به‌روز می‌شوند.
- **نقشه‌ی واقعی دانلود** و جدول اتصال‌ها (بازه، دریافتی، سرعت، وضعیت، تلاش مجدد، کد HTTP) با جزئیات قابل‌بازشدن برای هر اتصال. با کلیک روی یک بخش نقشه، اتصالی که آن بخش را می‌گیرد پیدا می‌شود.
- **موتور تقسیم پویا:** یک برنامه‌ریز مرکزی بازه‌ها را بین اتصال‌ها پخش می‌کند. وقتی کاری نمانده باشد، اتصال بیکار نصف بزرگ‌ترین بازه‌ی در حال دانلود را برمی‌دارد، پس یک اتصال کند کل دانلود را عقب نمی‌اندازد.
- **تعداد اتصال خودکار:** از ۴ شروع می‌شود و بر اساس سرعت کل بالا یا پایین می‌رود (تا ۱۶). با خطای 429 یا 503 یا قطع اتصال، کم می‌شود. یا مقدار ثابت ۱ تا ۳۲ را انتخاب کنید.
- **اعتبارسنجی سخت‌گیرانه‌ی Range:** وضعیت 206، شروع و پایان Content-Range، حجم کل و Content-Length. پاسخ نادرست هرگز نوشته نمی‌شود.
- **ادامه‌ی امن:** `If-Range` با ETag/Last-Modified. اگر فایل روی سرور عوض شده باشد، داده‌ی قدیمی با داده‌ی جدید ترکیب نمی‌شود و علتش در پنجره‌ی جزئیات نوشته می‌شود.
- **تلاش مجدد:** backoff نمایی با jitter، احترام به `Retry-After`، و قاعده‌ی جدا برای هر کد خطا. 401 و 403 و 404 بی‌نهایت تکرار نمی‌شوند.
- **ذخیره‌ی مطمئن:** هر ثانیه ابتدا داده روی دیسک ذخیره (fsync) و بعد فایل وضعیت نوشته می‌شود. فقط بایت‌هایی که واقعاً ذخیره شده‌اند «دریافت‌شده» حساب می‌شوند.
- **جستجو** (نام، آدرس، دسته، وضعیت)، **مرتب‌سازی** با ۹ معیار، و **منوی راست‌کلیک کامل**.
- محدودیت سرعت برای هر دانلود، و عملیات بعد از اتمام هر دانلود (باز کردن فایل یا پوشه، خاموشی، هایبرنیت).
- واحدها 1024-پایه و با نام درست نمایش داده می‌شوند (KiB, MiB, GiB)، و تاریخ‌ها با `fa-IR` یا `en-US`.

**هنوز ساخته نشده:** هش جداگانه برای هر بخش فایل، DASH و HLS رمزشده، HTTP/3، رویدادهای تایپ‌دار، ویرایش کامل مشخصات، پروکسی هر دانلود. فهرست دقیق در `IMPLEMENTATION_REPORT.md`.

**مرحله ۴ (جدید):**
- **طراحی تازه:** شیشه‌ای (glass)، آبی فیروزه‌ای نئونی، الهام‌گرفته از Windows 11؛ نوار پیشرفت نئونی با نور متحرک، درخت دسته‌بندی مثل IDM، نقشه‌ی بخش‌های دانلود، و نمودار زنده‌ی سرعت
- **پنجره‌ی تأیید دانلود (مثل IDM):** برای هر دانلود مرورگر، اول نام فایل، حجم، قابلیت ادامه و پوشه‌ی ذخیره نشان داده می‌شود و با «شروع دانلود / بعداً / انصراف» تصمیم می‌گیرید. پوشه‌ای که انتخاب کنید برای دانلود بعدی پیش‌فرض می‌شود، مگر در همان پنجره عوضش کنید.
- **دقت و سلامت فایل:** بخش‌های ریزتر برای تعادل بهتر بین اتصال‌ها، بررسی پاسخ Range و تغییر فایل روی سرور، بررسی حجم نهایی و ذخیره‌ی امن روی دیسک قبل از نام‌گذاری نهایی

**مرحله ۲:** لیست دانلودها، پیشرفت/سرعت/زمان باقی‌مانده، توقف/ادامه/حذف، صف با تعداد هم‌زمان قابل تنظیم، دسته‌بندی خودکار، محدودکننده‌ی سرعت، رابط فارسی/انگلیسی.

**مرحله ۳ (جدید):**
- **افزونه‌ی مرورگر** (بالا) با کوکی و Referer
- **زمان‌بندی:** شروع و توقف صف در ساعت مشخص، و گزینه‌ی «بعد از پایان: خاموش شدن / هایبرنیت». خاموشی با ۶۰ ثانیه مهلت انجام می‌شود و یک نوار هشدار با دکمه‌ی «انصراف» نشان می‌دهد. این کار فقط بعد از یک شروع زمان‌بندی‌شده‌ی واقعی اجرا می‌شود، نه بعد از دانلودهای دستی.
- **سینی سیستم:** بستن پنجره برنامه را در سینی نگه می‌دارد (قابل خاموش کردن در تنظیمات). کلیک روی آیکون سینی پنجره را باز می‌کند و «خروج» ابتدا دانلودها را با امنیت متوقف می‌کند.
- **تک‌نمونه:** اجرای دوباره‌ی برنامه فقط پنجره‌ی اول را جلو می‌آورد.

## امنیت اتصال مرورگر

- سرور فقط روی `127.0.0.1:46873` گوش می‌دهد.
- درخواست باید از خود افزونه‌ی مرورگر بیاید (هدر Origin بررسی می‌شود) و کد اتصال را داشته باشد؛ پس صفحه‌های وب نمی‌توانند دانلود اضافه کنند.
- برای ادامه‌ی دانلودهای نیازمند ورود، هدرها (کوکی و …) در `downloads.json` داخل `%APPDATA%\com.rdm.downloadmanager` فقط به شکل رمزشده با DPAPI ذخیره می‌شوند و روی کامپیوتر یا کاربر ویندوز دیگر قابل خواندن نیستند.

## محدودیت‌های فعلی

- از ویدیوهای استریم فقط HLS ساده (بدون رمز) پشتیبانی می‌شود؛ DASH پشتیبانی نمی‌شود.
- دانلودهای مرورگر که با POST یا لینک blob شروع می‌شوند به RDM نمی‌روند و خود مرورگر می‌گیرد.
- توقف و ادامه با دقت حدود ۱ مگابایت انجام می‌شود (آخرین بخش ذخیره‌نشده دوباره گرفته می‌شود).
- پیش‌فرض HTTP/1.1 است؛ HTTP/2 با گزینه‌ی «خودکار» و HTTP/3 هنوز نه.
- تست‌ها: `cargo test -p rdm-core`. تست‌های برنامه‌ریز، صف‌ها، ماشین حالت و تحلیل هش اجرا و موفق بودند. تست‌های سرور آزمایشی نوشته شده‌اند ولی هنوز اجرا نشده‌اند (اجرای اول آن‌ها روی GitHub است).
- ماژول خاموشی/هایبرنیت فقط روی ویندوز کار می‌کند.

## ساخت بدون نصب Rust (با GitHub Actions)

اگر نمی‌خواهید Rust و ابزارهای چندگیگابایتی را روی کامپیوتر خودتان نصب کنید، فایل `.github/workflows/build.yml` این کار را روی سرورهای رایگان GitHub انجام می‌دهد و فقط فایل exe نهایی (چند ده مگابایت) را دانلود می‌کنید.
1. در github.com حساب رایگان بسازید و یک Repository جدید بسازید.
2. محتوای پوشه‌ی پروژه (نه خود فایل zip) را با «Add file ← Upload files» آپلود کنید.
3. در تب Actions روی «Build Windows app» و بعد «Run workflow» بزنید.
4. بعد از تمام شدن (حدود ۱۰ تا ۲۰ دقیقه)، وارد اجرای موفق شوید و از بخش Artifacts فایل `rdm-windows` را دانلود کنید.
